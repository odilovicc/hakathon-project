# Кубышка

Трекер денег с питомцем, который живёт на твоих накоплениях.

## Запуск

Рекомендуется Node.js 22 LTS. После смены версии Node переустанови зависимости:
`better-sqlite3` содержит нативный модуль, собранный для конкретной версии Node.

```bash
npm install
npm run seed   # демо-аккаунт с операциями, целью и питомцем
npm run dev    # клиент http://localhost:5173, API http://localhost:3001
```

Демо-вход: `demo@kubyshka.app` / `demo1234`.

Другие команды: `npm test`, `npm run build`, `npm run typecheck`, `npm run lint`, `npm run format`.

В PowerShell с запрещёнными `.ps1`-скриптами используй `npm.cmd` вместо `npm`.

## Seed

Демо-аккаунт использует UZS (сум). Seed создаёт историю операций, регулярные
платежи, цель на 40%, музей, ежедневные отчёты и питомца.

`npm run seed` пересоздаёт только демо-аккаунт, остальные аккаунты сохраняются.
Для обновления существующей базы достаточно перезапустить API: миграции применятся
автоматически, запускать seed не нужно.

## Структура

```
client/              React 18 + Vite + TypeScript + Tailwind v4
server/              Express 5 + TypeScript + better-sqlite3
  migrations/        SQL-миграции, применяются при старте
  data/kubyshka.db   файл базы (создаётся сам)
shared/              общие типы, контракты API и расчёты
```

Деньги везде хранятся целыми числами в минимальных единицах валюты (тиыны, копейки, центы).

## Знакомство с кубышкой

Главная `/` открывает лендинг для русскоязычной аудитории Ташкента. Он показывает
проблему незаметных повседневных расходов и решение через дневной остаток, экономию
и цель. Два интерактивных примера работают без аккаунта и не меняют пользовательские
данные. Кнопки ведут на `/register?currency=UZS`, где суммы уже выбраны в сумах.
Вход в кабинет остаётся доступен через `/login`.

Лендинг использует существующий React/Vite, обычный CSS, GSAP/ScrollTrigger и живой
SVG-компонент Кубыша. Есть мобильное меню, FAQ, светлая/тёмная тема и поддержка
уменьшенного движения. Изображение хранится локально; источник и промпт описаны
в [docs/landing-assets.md](docs/landing-assets.md).

Открой `/register`, создай аккаунт и пройди шесть шагов: доход, расходы, долги,
подушка, цель и график работы. Суммы вводятся в основных единицах выбранной валюты;
допустимы пробелы и десятичная запятая. Для цели сразу считается взнос в месяц.
Нулевой доход и цель без срока поддерживаются.

После кнопки «Дальше» ответы и номер следующего шага сохраняются на сервере.
Перезагрузка страницы или повторный вход возвращают на сохранённый шаг.
Несохранённые изменения текущего шага после перезагрузки нужно ввести снова.
Кнопка «Назад» позволяет проверить ответы. Ошибка сети оставляет введённые данные
в форме и позволяет повторить сохранение.

После шестого шага появляется яйцо-кубышка. Нажми «Познакомиться с кубышем», дай
ему имя и нажми «В кабинет». Создание питомца и завершение знакомства выполняются
одной транзакцией; повторный запрос не создаёт второго питомца.
Анимации учитывают `prefers-reduced-motion`, интерфейс работает от 360 px и в тёмной теме.

Маршруты:

- `/login`, `/register` — вход и регистрация.
- `/onboarding` — знакомство для незавершённых аккаунтов.
- `/app` — Сегодня: бюджет, график расходов, топ категорий и отчёт дня.
- `/app/transactions` — календарь операций с итогами месяца и выбранного дня, добавлением, редактированием и удалением.
- `/app/goal` — цель, накопления, кубыш, гардероб и прогноз.
- `/app/museum` — покупки, от которых удалось отказаться, и перевод их стоимости в цель.
- `/app/subscriptions` — регулярные платежи, статусы и экономия после отмены.
- `/playground` — прежняя витрина персонажа.

Миграция `003_onboarding_progress.sql` применяется при запуске сервера автоматически.
Она добавляет номер шага, сохраняя существующие профили и завершённый онбординг.
Серверные тесты проверяют восстановление прогресса, запрет раннего завершения,
валидацию имени и повторное завершение без дубликатов.

## Кабинет и отчёт дня

На странице «Сегодня» показаны дневной лимит, потраченное сегодня и остаток.
Лимит равен бюджету на начало дня, разделённому на оставшиеся дни до зарплаты.
Каждый сегодняшний расход вычитается из лимита целиком; превышение показано явно.
Неиспользованный бюджет распределяется заново на следующий день. Подробный расчёт
с доходом из профиля, резервами на подписки и цель, прошлыми расходами раскрывается
по запросу. Оплаченные зарезервированные подписки не вычитаются повторно.
График показывает повседневные расходы; ниже три главные категории.
Изменения операций сразу обновляют бюджет, график и историю.
Навигация расположена сбоку от 1024 px, на узких экранах снизу.

Операции открываются календарём. Нажатие на дату показывает итоги и записи дня
с действиями «Изменить» и «Удалить». Новая операция получает выбранную дату;
при переносе записи на другую дату открывается новый день. Итоги месяца включают
все записи, а список дня разбит на страницы по 50. Фильтры по типу, категории и
заметке применяются одновременно к календарю и списку. На телефоне выбор даты
переводит к записям дня, «К календарю» возвращает к выбранной дате.
Клавиатура: стрелки перемещают выбор, Home/End переходят к границам недели,
PageUp/PageDown переключают месяц.
Для расходов показано рабочее время: сумма / месячный доход × часов в день × рабочих дней в месяц.
При нулевом доходе интерфейс объясняет, почему время не рассчитано.

«Отчёт дня» принимает сумму, в том числе ноль, и одно из трёх ощущений.
Если за день нет ни одной операции и сумма положительна, создаётся расход
«Расход за день» в категории «Другое». При наличии операций отчёт не добавляет
расход; забытые покупки нужно записать отдельно. Дата определяется по локальному
времени сервера. Повторная отправка возвращает сохранённый отчёт без новых изменений.

Отчёт даёт +25 к настроению (не выше 100) и один день заботы. За каждый законченный
день без отчёта настроение снижается на 15 (не ниже 0); расчёт выполняется при
авторизованном запросе. Дни заботы не обнуляются. Аура меняется на 10, 20, 30, 40
и 60 днях заботы; переход сопровождается короткой анимацией и конфетти.
При `prefers-reduced-motion` движения и конфетти отключены.

Тесты покрывают нулевой отчёт, повторные и параллельные запросы, отсутствие двойного
расхода, атомарность сохранения, пропуски, диапазон настроения, ауры и часы работы.
Браузерные сценарии проверены на 360 и 1440 px, включая ошибки сети и повторную отправку.

## Цель и кубыш

В `/app/goal` можно изменить цель, пополнить её или снять часть накоплений.
Это учёт перемещения накоплений: записи не создают дополнительный доход или расход
в операциях. Снять больше накопленного нельзя. Суммы хранятся в минимальных единицах
валюты; максимальный остаток — 100 миллиардов основных единиц.

Костюмы открываются на 15/30/45/60/75/90% и сразу надеваются. Шапка и корона
занимают один слот: выбор одной снимает другую. Вещи можно снимать вручную.
Если после снятия денег или изменения размера цели процент опускается ниже порога,
вещь уходит в сундук. На прежнем пороге доступ восстанавливается; ранее надетая вещь
возвращается на кубыша, а снятая вручную остаётся в гардеробе. Костюмы видны также
на странице «Сегодня» и в боковой панели.

При 100% появляется праздничный экран, цель получает статус `done`, кубыш растёт
на одну стадию (максимум 3). Эволюция выдаётся только один раз за цель: снятие и
повторное достижение 100% не дают ещё одну стадию. Снятие с завершённой цели снова
делает её активной, но сохраняет достигнутую стадию. Новая цель доступна после
завершения: старая вместе с накоплениями остаётся в истории, новая начинается с нуля.
Гардероб зависит от процента новой цели.

«Будущий ты» использует чистые пополнения текущей цели за последние 30 дней
(все взносы минус снятия). Срок — оставшаяся сумма / темп, с округлением вверх до
месяца; второй вариант использует темп +10%. При нулевом или отрицательном темпе
срок не показывается. Это оценка при сохранении темпа, а не обещанная дата.

История взносов и снятий разбита на страницы по 20 записей. Пополнение, событие,
костюмы и эволюция сохраняются одной транзакцией. Клиент передаёт `goalId` и UUID
`requestId` в `/goal/deposit` и `/goal/withdraw`: повтор того же запроса не меняет
накопления второй раз. При потере ответа форма предлагает безопасный повтор;
после закрытия формы нужно проверить историю перед новой операцией.

Дополнительные API: `GET /goal/details?page=1`, `GET /pet/costumes`,
`PUT /pet/costumes/:id/activate {active: boolean}`. Миграция
`004_goal_rewards.sql` применяется автоматически при запуске сервера.

## Музей и подписки

В музее можно записать название несостоявшейся покупки, стоимость и категорию
расходов. Сверху показаны общая стоимость экспонатов и уже направленная в копилку
сумма. Если у цели есть срок и положительный плановый взнос, общая стоимость также
переводится в месяцы взносов. У каждого экспоната указано сохранённое рабочее время;
при нулевом доходе интерфейс объясняет отсутствие расчёта.

После добавления появляется предложение перевести стоимость покупки в цель.
Создание экспоната защищено UUID `requestId`: потерянный ответ можно повторить
без второй записи. После закрытия формы сначала проверь музей.

Подписки находятся по расходам с одинаковой заметкой (регистр и лишние пробелы
не учитываются) и суммой в пределах ±5% в соседних календарных месяцах. Будущие
операции и пустые заметки не участвуют. Это простой детект, поэтому интерфейс
предлагает проверить найденные платежи. Найденные подписки сохраняются как записи;
их статус не сбрасывается при последующем детекте. Последняя подходящая сумма
обновляет активную автоматически найденную подписку. Можно добавить месячный или
годовой платёж вручную, одинаковые названия не дублируются.

«Не пользуюсь» показывает потенциальную экономию за год, сохраняя платёж в бюджете.
«Отменил» убирает будущий резерв. Уже оплаченные операции остаются в расходах.
При активном резерве один совпавший платёж за календарный период исключается из
повседневных расходов, чтобы не считать его дважды; дополнительные оплаты остаются
расходами. Годовые платежи приводятся к месяцу с округлением до минимальной единицы.
Отметка в приложении не отменяет услугу у поставщика.

У отменённой подписки можно один раз направить месячную сумму в цель. Переводы
из обоих разделов обновляют накопления, гардероб, сундук и эволюцию через общую
логику цели, дают +10 к настроению (максимум 100) и показывают реплику кубыша.
Дни заботы не увеличиваются. Перевод не создаёт новую доходную или расходную
операцию. Источник, событие цели, костюмы и корм сохраняются атомарно; повтор
запроса, повторная отмена или создание новой цели не дают повторного зачисления.
Без цели запись сохраняется, а интерфейс предлагает создать цель.

API: `GET/POST /museum`, `POST /museum/:id/transfer`, `GET/POST /subscriptions`,
`POST /subscriptions/:id/status {status: 'active'|'unused'|'cancelled'}`,
`POST /subscriptions/:id/transfer`. Миграции `005_museum_subscriptions.sql` и
`006_museum_requests.sql` применяются автоматически при запуске.

Проверены автодетект на границах ±5%, соседние месяцы и смена года, ручные годовые
подписки, доступ к чужим данным, повторы, сохранение статусов, расчёт бюджета,
откат при ошибке и перевод после смены цели. В браузере проверены 360 и 1440 px,
светлая/тёмная темы, reduced-motion, потеря связи, гардероб и эволюция.

## Пересмотр интерфейса

Уменьшены общие размеры, упрощены подписи и порядок информации на всех существующих страницах. Назначение и главное действие видны в начале страницы, вторичные сведения раскрываются по запросу. Подтверждение записи накоплений показывает сумму и цель; необязательное поле API `{goalId}` защищает от записи в заменённую цель. Подробности и результаты проверки: [UX_REVIEW.md](UX_REVIEW.md).

## Категории операций

Доступны 27 системных категорий расходов и 5 категорий доходов. В расходах есть
коммунальные услуги, такси, автомобиль, образование, дети, красота и уход, спорт,
питомцы, путешествия, техника, ремонт, кредиты и долги, налоги и штрафы,
благотворительность, услуги, кофе и перекусы, а также прежние категории.

В форме сначала видны основные категории и текущий выбор. «Все категории» открывает
полный список с поиском; «Своя категория» позволяет создать личную категорию и сразу
выбрать её. Категория применяется и при редактировании операции, и в фильтрах календаря.
Личные категории доступны только владельцу, типы доходов и расходов разделены.

Миграция `010_expense_categories.sql` добавляет категории существующим аккаунтам
без изменения прежних идентификаторов и операций. Миграция `009_remove_shopping.sql`
удаляет таблицы исключённого магазинного каталога. Накопления, события целей,
питомцы и операции сохраняются. Старые SQL-миграции оставлены для последовательного
обновления существующих баз; интеграции карт и сравнения магазинов в приложении нет.
